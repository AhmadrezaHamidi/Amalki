# سرعت سایت: چک‌لیست ۳۱ موردی

وضعیت هر مورد در Royal Fine Homes (۲۰۲۶-۱۱-۰۷). «از قبل» یعنی پیش از این کار انجام شده بود؛ «جدید» یعنی در این مرحله اضافه شد.

## نتیجهٔ اندازه‌گیری

گوشی میان‌رده (۴۱۲×۸۲۳، پردازنده ۴ برابر کندتر) با اینترنت کند موبایل (Slow 4G: ۱٫۶ مگابیت، تأخیر ۱۵۰ میلی‌ثانیه)، اولین بازدید، روی سایت منتشرشده (Production) با SQL Server 2022 و آگهی‌های نمونه. ابزار: [`tools/perf/slow-phone.js`](../tools/perf/slow-phone.js).

| صفحه | LCP قبل | LCP بعد | حجم دانلود قبل | حجم دانلود بعد |
|---|---|---|---|---|
| صفحهٔ اصلی | ۵٫۵ ثانیه | ۱٫۲ ثانیه | ۱۱۳۰ KB | ۱۹۹ KB |
| فهرست آگهی‌ها | ۶٫۰ ثانیه | ۰٫۴ ثانیه | ۱۲۷۵ KB | ۸۴ KB |
| صفحهٔ آگهی | ۲٫۵ ثانیه | ۰٫۵ ثانیه | ۵۱۷ KB | ۳۷ KB |

HTML صفحهٔ اصلی از ۳۹ KB به ۹ KB رسید (Brotli). بیشترین اثر از عکس‌های نمونه بود: JPEG ۲۲۰ تا ۵۰۰ KB بدون نسخهٔ WebP؛ حالا گوشی نسخهٔ ۴۸۰ پیکسلی ۱۰ تا ۳۰ KB را می‌گیرد.

```bash
node tools/perf/slow-phone.js https://royalfinehomes.ir / /املاک
```

## چک‌لیست

|---|---|---|---|
| 1 | اسکلت لودینگ | جدید | کادر عکس‌ها تا رسیدن عکس موج می‌خورد؛ هنگام رفتن به صفحهٔ بعد یا اعمال فیلتر، کارت‌ها کم‌رنگ می‌شوند؛ پیشنهادهای جست‌وجو هم اسکلت دارند (`site.css`، `site.js`). صفحه‌ها سمت سرور کامل ساخته می‌شوند، پس اسکلتِ کل صفحه لازم نیست. |
| 2 | عکس WebP/AVIF | از قبل + جدید | عکس‌های آپلودی از قبل سه نسخهٔ WebP (۴۸۰/۹۶۰/۱۶۰۰) و `srcset` داشتند. جدید: عکس‌های نمونه هم نسخهٔ WebP دارند (`wwwroot/img/demo/*-480.webp`) و دیتابیس‌های قبلی هنگام شروع به‌روز می‌شوند. | 4 | جستجو Debounce | جدید | پیشنهاد شهر و محله زیر جعبهٔ جست‌وجو (`/api/suggest`)، ۲۵۰ میلی‌ثانیه بعد از توقف تایپ. |
| 5 | صفحه‌بندی API | از قبل + جدید | فهرست عمومی ۱۲تایی، آگهی‌های پنل ۵۰تایی از قبل. جدید: درخواست‌های تماس پنل ۵۰تایی (قبلاً ۵۰۰ ردیف یکجا). |
| 6 | CDN | آماده | همهٔ فایل‌های ثابت هدر کش درست دارند، پس یک CDN (مثلاً ابرآروان) بدون تغییر کد جلویش می‌نشیند. پایین‌تر را ببینید. |
| 7 | صف پس‌زمینه | از قبل | Outbox + `OutboxProcessor` (کانال‌ها، هشدار مدیر، پیامک، پاک کردن فایل) و `CampaignWorker` برای پیامک گروهی؛ هیچ‌کدام درخواست کاربر را معطل نمی‌کنند. |
| 8 | رفع N+1 | جدید | پیامک گروهی آگهی را برای هر گیرنده دوباره می‌خواند (۱۰٬۰۰۰ گیرنده = ۱۰٬۰۰۰ کوئری)؛ حالا یک بار. فهرست پنل از قبل کاور عکس‌ها را در یک کوئری می‌گرفت. |
| 9 | Gzip/Brotli | جدید | `UseResponseCompression` برای HTML/JSON/XML (Brotli، بعد gzip). CSS/JS از قبل پیش‌فشرده بودند. |
| 10 | کش Redis | جدید (اختیاری) | با `Redis__Connection` کش خروجی و کلیدهای Data Protection در Redis می‌روند؛ برای چند سرور لازم است. بدون آن کش در حافظهٔ همان سرور است. |

| 14 | آپدیت خوش‌بینانه | از قبل | «نشان کردن» فوراً روی صفحه عوض می‌شود (در مرورگر ذخیره می‌شود، منتظر سرور نیست). |
| 15 | عکس Lazy Load | از قبل + جدید | همهٔ عکس‌ها `loading="lazy"` و نقشه هم lazy. جدید: عکس اولین کارت فهرست برعکس، فوری و با اولویت بالا (LCP). |
| 16 | درخواست همزمان | جدید | صفحهٔ اصلی سه کوئری مستقل را هم‌زمان روی سه context جدا اجرا می‌کند. |

## تنظیمات

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `Performance__RequestTimeoutSeconds` | `20` | سقف زمان هر صفحه (پاسخ 504) |
| `Database__CommandTimeoutSeconds` | `15` | سقف هر کوئری SQL |
| `Redis__Connection` | خالی | مثلاً `redis:6379`؛ کش خروجی و کلیدها در Redis |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | خالی | مثلاً `http://otel-collector:4317` |
| `OTEL_SERVICE_NAME` | `amlak-web` | نام سرویس در ردیابی |

## چند سرور پشت Load Balancer

```nginx
upstream amlak { least_conn; server 10.0.0.11:8080; server 10.0.0.12:8080; }
server {
    listen 443 ssl http2;
    server_name royalfinehomes.ir;
    location / {
        proxy_pass http://amlak;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

- روی هر سرور `Redis__Connection` یکسان و `Proxy__KnownProxies` را IP همین nginx بگذارید.
- بررسی سلامت: `GET /healthz` (۲۰۰ یعنی به SQL Server وصل است).
- محدودیت نرخ فرم‌ها (`AddRateLimiter`) هنوز برای هر سرور جداست؛ با دو سرور، سقف واقعی دو برابر است.

## CDN

- فایل‌های `/css`، `/js` (اثر انگشت‌دار، یک سال)، `/uploads` (یک سال)، `/fonts`، `/img`، `/icons` (یک هفته) را CDN می‌تواند کش کند.
- HTML را CDN کش نکند (یا حداکثر چند ثانیه): کش خروجی خود سایت با هر تغییر آگهی پاک می‌شود اما کش CDN نه.
- عکس‌ها روی MinIO هستند؛ `PHOTOS_URL` را به زیردامنهٔ CDN بدهید (docs/DEPLOY.md).
